# 本地预览与 Vercel 部署

本项目使用同一套 Next.js 应用连接不同 Neon 分支。Vercel 负责应用部署，Neon 保存结构化内容，又拍云保存照片文件。以下为配置与发布流程，实际部署状态以 Vercel 部署记录和目标数据库核验结果为准。

## 本地预览

安装 Node.js 24.x，在项目目录执行 `npm ci`。首次使用时将 `.env.example` 复制为 `.env.local`，填写开发分支连接串和后台密码；不要覆盖已有凭据文件。

建议从现有生产分支创建独立 Neon 开发分支，保留基础表及站点初始内容。开发分支建立后，两边的编辑不自动同步；数据库分支也不会复制图床文件。

```powershell
npm run check:env
```

确认目标是开发分支后，如需迁移旅行表，将 `PREVIEW_READ_ONLY=false` 并执行：

```powershell
node scripts/migrate-travel.mjs
npm run preview
```

访问 [http://127.0.0.1:3100](http://127.0.0.1:3100)，后台为 [/admin](http://127.0.0.1:3100/admin)。`preview` 使用仅监听本机的开发服务器，按 Ctrl+C 停止；生产构建用 `npm run build` 验证。

Windows 后台启停：

```powershell
powershell -File .\scripts\start-preview.ps1
powershell -File .\scripts\stop-preview.ps1
```

按需分别执行启动或停止命令。日志位于 `.local-preview/stdout.log` 和 `.local-preview/stderr.log`；端口被其他项目占用时启动脚本会退出。不要同时启动前台和后台两份预览。

管理员使用 `ADMIN_PASSWORD` 登录。修改本地密码后重启预览，修改 Vercel 密码后重新部署。当前登录实现也使用该值签名会话；项目不读取 `AUTH_SECRET`。

## 环境变量

| 变量 | 用途与取值 |
| --- | --- |
| `DATABASE_URL` | Neon PostgreSQL 连接串，保留提供的 TLS 参数。本地和生产分别使用各自分支。 |
| `POSTGRES_URL` / `POSTGRES_PRISMA_URL` | 兼容连接变量，优先级为 `DATABASE_URL` → `POSTGRES_URL` → `POSTGRES_PRISMA_URL`。避免配置到不同数据库。 |
| `ADMIN_PASSWORD` | 后台密码，各环境分别设置，不提交到 Git。 |
| `PREVIEW_READ_ONLY` | `true` 禁止内容写入；`false` 允许后台编辑。`.env.example` 默认只读。 |
| `PREVIEW_DEMO` | 只有设为 `true`、未配置数据库且不在 Vercel 时才启用内置示例；示例始终只读。 |
| `LOCAL_PREVIEW_LABEL` | 可选本地提示文字，例如 `Neon 开发分支`；仅非 Vercel 环境显示，启用后本地页面禁止索引。 |
| `NEXT_PUBLIC_UPYUN_HOSTS` | 逗号分隔的又拍云域名，填写纯域名，不带协议、端口、路径或通配符；内置 `img.ixzki.com`。 |
| `NEXT_PUBLIC_UPYUN_TRANSFORMS` | 默认开启又拍云图片处理；设为 `false` 停止追加处理参数，适用于不支持处理或需要保留签名参数的图片地址。 |
| `IMAGE_REMOTE_HOSTS` | 可选其他 HTTPS 图片域名白名单，格式同上。 |
| `NEXT_PUBLIC_TRAVEL_TILE_URL` | 可选地图瓦片 URL 模板，包含 `{z}`、`{x}`、`{y}`；默认使用 OpenStreetMap。替换服务时同时核对服务授权及页面署名。 |

`NEXT_PUBLIC_` 变量会进入浏览器构建产物，不能存放秘密。修改公开变量或图片域名白名单后，本地重启、线上重新构建部署。已配置但连接失败的数据库会报错，不会静默切换为示例数据。

## 内容存储与图片

| 内容 | 保存位置 | 发布时如何处理 |
| --- | --- | --- |
| 应用代码、页面样式、迁移脚本 | GitHub | 推送提交后由现有 Vercel 项目部署。 |
| 作品、精选、媒体元数据、站点设置 | Neon 基础表 | 对比源分支与生产数据，单独同步需要发布的记录。 |
| 旅行轨迹、点位、Markdown、封面与发布状态 | `portfolio_travel` | 单独同步完整旅行文档，并保持表字段与 JSON 内容一致。 |
| 照片文件 | 又拍云 | 继续使用已有公开 URL；数据库同步只同步 URL。 |
| 原始足迹 CSV、凭据、日志与备份 | 本地或受控备份位置 | 不随应用提交或部署。 |

图片后台不提供又拍云文件上传接口，也不需要图床操作员密钥。媒体库保存图片 URL 和元数据；删除媒体记录不会删除图床文件。图片地址统一使用 `img.ixzki.com`。

CSV 在浏览器 Worker 中解析，按选定日期筛选后保存轨迹；原始完整文件不会上传。坐标要求 WGS84，无时区时间按北京时间 UTC+8 处理。发布前应确认起止时刻，导入器不会自动识别航班。详细格式见 [CSV 导入说明](./travel-csv-import.md)。

旅行后台可添加吸附于轨迹的点位、选取线路段、手绘折线，并为正文编写 Markdown。手绘不会自动规划公路导航；原始 HTML 不执行。发布需要封面、有效路线与正文，草稿允许先保存未完成内容。作品后台按信息、展示图片、图片编排和设置分区，图片描述、顺序和跨行移动均随“保存作品”操作写入数据库。

## 数据库迁移与内容同步

基础表为 `portfolio_settings`、`portfolio_projects`、`portfolio_features` 和 `portfolio_media`。`/setup` 是说明页，不建表；新开发环境应优先从已配置的生产分支创建。`check:env` 检查基础表和记录数，不写数据，也不检查旅行表。

旅行迁移脚本为：

```powershell
node scripts/migrate-travel.mjs
```

脚本读取当前进程及项目环境配置。执行前必须确认目标连接与写入权限；不要以为在本地运行就一定连接开发分支，也不要仅为运行迁移把 Vercel Production 指向开发库。

该脚本在事务中创建 `portfolio_travel`、`portfolio_travel_migrations`，并通过 `seed-xinjiang-2026-v1` 标记一次性写入仓库中的新疆种子。重跑不覆盖已有编辑，也不恢复已删除的旅行。它不修改基础内容表，且**不会迁入开发分支后来新增、改名或编辑的旅行**。

同步当前后台内容到生产时，将结构迁移和数据同步作为独立步骤：

1. 核对源分支、生产分支以及双方最新内容，导出目标数据备份并保留恢复方式。
2. 在目标数据库补齐旅行表和迁移标记，确认一次性种子与待同步内容之间是否存在旧名称或重复路线。
3. 按已确认的内容范围同步作品、精选、设置、媒体元数据和旅行文档；核对 ID、网址标识、公开状态、排序、图片域名和旅行版本。保留未纳入同步范围的生产记录，不将整库覆盖当作默认操作。
4. 比对同步前后记录及完整内容，检查新增旅行、旧路线改名、作品关联等结果。数据同步后发布新应用或刷新相应页面缓存，避免旧缓存掩盖数据库变化。

旅行后台保存采用 `revision` 乐观锁；多窗口编辑遇到 409 时应重新加载最新内容。跨分支同步也应保留并核对版本信息，避免把较旧内容覆盖到生产。

## 现有 Vercel 项目发布

沿用当前关联 GitHub 仓库的 Vercel 项目。根目录指向包含 `package.json` 的目录，框架使用 Next.js，Node.js 为 24.x，安装命令 `npm ci`，构建命令 `npm run build`。本地 `preview` 命令和 PowerShell 启停脚本不作为 Vercel 启动命令。

| 配置 | 本地开发 | Vercel Preview | Vercel Production |
| --- | --- | --- | --- |
| 数据库 | 独立开发分支 | 独立测试分支 | 现有生产分支 |
| 后台密码 | 本地密码 | 测试密码 | 生产密码 |
| `PREVIEW_READ_ONLY` | 编辑时为 `false` | 只展示为 `true`，测试编辑为 `false` | 需要后台编辑时为 `false` 或不设置 |
| `PREVIEW_DEMO` | 通常为 `false` | `false` 或不设置 | `false` 或不设置 |
| 图片和瓦片配置 | 开发所需地址 | 与待发布配置一致 | 正式地址 |

在 Vercel 项目设置中分别选择环境变量所属环境。开发连接串不应同时应用到 Production；多个预览共用一个开发分支时也会共享编辑结果。环境变量修改后需创建新部署。

发布流程：

1. 更新 README 和相关文档，检查提交范围，排除环境文件、原始 CSV、数据库导出和本地日志。
2. 执行下列检查；`build` 会读取数据库，需有正确连接和必要表。

   ```powershell
   npm test
   npm run lint
   npm run check:env
   npm run build
   ```

3. 按上一节完成目标数据库迁移及确认的内容同步，再将已核验提交推送到关联仓库。根据该项目 Git 配置创建 Preview 或 Production 部署，确认最终部署的提交号及环境。
4. 在正式域名验证首页、作品详情、旅行总图、旅行详情滚动、后台登录和图片加载；核对旅行标题、路线数量及内容。需要写入验证时使用可清理的临时记录，并在验证后删除。

代码发布、数据库同步和网页可用性应分别记录结果；某一项成功不能代替其他项目的验证。测试数量与数据库记录数会随开发变化，以本次实际输出为准。

## 回退与排查

回退代码可选择 Vercel 中之前验证过的部署，但应用回退不会回退 Neon 数据。数据库内容恢复使用同步前备份或数据库恢复能力，并核对与回退代码的兼容性；保留恢复前后的数据，不通过删除或重建生产分支回退应用。

| 现象 | 检查方法 |
| --- | --- |
| 首页进入 `/setup` | 检查数据库变量、示例模式，运行 `npm run check:env`。 |
| 连接成功但缺少基础表 | 确认是否误连空库；开发环境可从现有生产分支创建。 |
| 旅行后台提示尚未迁移 | 核对目标数据库并执行旅行表迁移；页面读取不会自动建表。 |
| 发布代码后缺少新游记 | 核对 Production 是否连接正确分支，以及是否单独同步了旅行内容。 |
| 后台无法保存 | 检查登录、只读配置、字段错误和返回信息；旅行 409 表示版本冲突。 |
| 图片返回 403 或不显示 | 检查原始 URL、域名白名单、又拍云防盗链、签名和处理参数；本地与 Vercel 来源可能不同。 |
| 地图底图不可用 | 检查瓦片服务网络和 URL 配置；确认当前服务允许应用的访问方式。 |
| 修改环境变量未生效 | 本地重启，Vercel 重新部署；公开变量需要重新构建。 |

仓库保留可重复使用的环境检查、旅行迁移及本地预览启停脚本。早期绑定某个 Neon 开发分支的一次性连接和验证脚本已清理；环境配置使用 `.env.local`，自动检查使用 `npm test` 和 `npm run check:env`。需要写入验证时，在独立开发分支使用临时记录并清理，验证结果存放在被 Git 忽略的 `.local-preview/`。

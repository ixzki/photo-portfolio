# 旅行后台与部署

旅行后台位于 `/admin/travel`，使用现有管理员登录。CSV 在浏览器中解析，选定旅行时间范围后才保存路线；原始完整足迹文件不传入 Neon，也不随网站发布。

## Neon 初始化

在目标环境的项目目录中，配置对应 Neon 分支的 `DATABASE_URL`，然后执行：

```powershell
node scripts/migrate-travel.mjs
```

本地使用 `.env.local` 中的独立开发分支。部署到 Vercel 前，对目标生产或预览数据库各运行一次迁移；不要把开发连接串直接替换到生产。

脚本默认只创建 `portfolio_travel` 和 `portfolio_travel_migrations` 两张表，不写入旅行内容。如需在独立示例数据库填入演示路线，显式执行 `node scripts/migrate-travel.mjs --seed-example`。示例包含 2 段合成轨迹、49 个点和 9 处正文。一次性标记和示例写入在同一事务中；重跑不会覆盖编辑，也不会恢复已删除的示例。已有作品、设置、媒体库不受影响。只读预览会拒绝迁移。

页面读取不执行建表或种子写入。只有尚未迁移导致旅行表不存在时，前台临时使用合成示例路线；数据库连接异常不会被静默替换成示例。迁移后没有已发布旅行时，前台显示空地图。

## 编辑与发布

1. 在“旅行管理”打开已有路线继续编辑，或点击“新建旅行”。填写标题和网址标识，在“首屏大图”粘贴图床地址或选择媒体库图片。
2. 展开“导入 CSV”，选择文件后自动识别并填入开始、结束时间（北京时间）。如文件包含多次旅行，可手动缩小范围；“重新识别时间”可恢复文件的完整范围。点击“读取 CSV”核对点数、已记录距离、时长及实际起止时间。新建旅行点击“应用导入轨迹”；已有路线若各段及坐标逐点一致，可用“仅更新时间和海拔（保留正文）”安全补齐记录。直接“应用导入轨迹”仍会提示清空关联正文；保存前不会改变数据库里的版本。
3. 点击“添加点位”后在地图上选一个地点；点击“选取路段”后依次选择起点和终点。位置会吸附到轨迹，可用右侧的轨迹点序号精调，同一地点多次经过时用序号区分。
4. “手绘线路”允许依次点击地图绘制新的折线，可以撤销最后一笔；完成后会追加线路并建立对应正文段。手绘线按点击位置连接，不自动计算公路导航路线。
5. 在左侧行程列表选择正文，修改名称并编写 Markdown。勾选“设为全程地图精选点位”，可让它在详情页全程地图的滚动动画中显示名称、时间和海拔；列表会标明“精选”，右侧预览对应信息。可以点击“插入图片”使用图床链接或媒体库，再切换“预览”检查排版。
6. 点击“保存草稿”保存编辑；勾选“公开展示”后“保存并发布”，旅行总地图和详情页即使用保存内容。取消勾选再保存即可隐藏旅行。

在“浏览”模式下，选中的地点可拖动重新定位；路段可通过“在地图上选起点 / 终点”修改范围。“轨迹管理”可以删除整条线路，这也会删除与它相交的正文；删除一个正文点位或路段则保留轨迹本身。

Markdown 示例：

```markdown
沿着山路进入草原，傍晚在这里停下。

![草原上的夕阳](https://images.unsplash.com/photo-1501785888041-af3ef285b470?auto=format&fit=crop&w=1800)

> 这一段最喜欢的风景。

- 停留：两小时
- 路况：铺装道路
```

新建旅行默认为草稿。草稿可以先保存空路线、空封面和空正文；发布需要封面、至少两点的路线、至少一个地点或线路段正文，以及文字或图片内容。正文区支持 Markdown。没有启用原始 HTML，因此 HTML 标签不能在浏览器执行。图片链接保留填写的域名；更换图床时请自行更新地址，并在环境变量中配置允许的域名。

正文锚点按照轨迹点顺序保存。点位吸附到对应轨迹坐标；线路段包含起点和终点，可以跨 CSV 断采样区间，地图仍保留断轨。一个线路段的终点不能越过下一段正文的起点，以保证向下阅读时路线向前推进。

精选选择保存在正文项的可选布尔字段 `featured`，只接受 `true` / `false`；省略时为未精选。无需新增数据库表或运行迁移。移动点位会保留选择，删除正文或对应线路会同步移除，重新导入 CSV 清空正文时也清空精选。取消勾选并保存即可停止在全程地图标注，不删除正文内容。

CSV 中的时间与海拔存为 `journey.pointMeta`，与展开后的坐标一一对应。正文、精选标注和后台预览统一使用北京时间格式，例如 `25/9/29 5PM 1335M`；月份和日期不补零，小时使用 AM/PM，海拔以大写 M 结尾。路段展示起止时间和海拔范围；列表修改时间及导入结果也使用相同日期格式。调整锚点会使用新锚点的记录，删除线路会同步移除其元数据，手绘新增点使用空值。旧旅行缺少这些字段时不会捏造数值，需从原始 CSV 补齐。

后台通过 `/api/travel` 读写，均需管理员身份。写入还检查请求来源、只读预览状态、路线和图片数据。JSON 请求上限为 3500000 字节，路线最多 100000 个坐标、正文最多 200 段；这样选定后的路线可在 Vercel 函数请求体限制内保存。超出时应缩小导入时间范围或简化轨迹。

每次保存递增 `revision`；更新和删除用数据库原子版本比较。两个窗口同时编辑时，旧版本请求返回 409，不覆盖较新的内容。保存或发布后会刷新旅行列表和详情页缓存。

## API 契约

| 操作 | 请求 | 成功返回 |
| --- | --- | --- |
| 列表 | `GET /api/travel` | `TravelSummary[]` |
| 详情 | `GET /api/travel?id=ID` | `TravelDocument` |
| 新建 | `POST /api/travel`，完整文档、revision 为 0 | 文档、revision 为 1；201 |
| 更新 | `PUT /api/travel`，完整文档和读取时的 revision | 文档、revision 加 1；200 |
| 删除 | `DELETE /api/travel?id=ID&revision=N` | `{ "ok": true }` |

校验失败为 400，未登录为 401，跨站写入或只读预览为 403，不存在的详情为 404，重复网址或版本冲突为 409，请求超限为 413，数据库暂时不可用为 503。错误响应不返回连接串、SQL 或底层驱动异常详情。

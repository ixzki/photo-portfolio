# 旅行页面与阅读版式

`/travel` 从 Neon 读取已发布旅行，以整屏灰色底图展示不同灰度的路线；不叠加路线标题，不显示页脚。点击路线或聚焦后按 Enter 进入 `/travel/[slug]`。透明的 22px 点击区域方便触摸，悬停与聚焦时路线变黑。

## 详情页的阅读顺序

1. **封面**：沿用作品详情整屏大图、右下角反色标题和原有动效；标题上方是白色完整路线轮廓，带黑色描边。左下方并排显示已记录路线的总公里数与行程时长，与右侧路线标题使用同一字号、行高和底边，上方用小字显示北京时间起止时间，不添加副标题。左侧信息跟随右侧标题的显隐状态，下滑时向左移动 18px 并淡出，上滑时回到原位；两侧均使用 0.42 秒透明度和 0.62 秒位移动画，减少动态效果时直接切换。距离不显示“约”，只累加连续轨迹段，不跨记录中断补线；时长包含停留与过夜，按整小时显示天数与小时，不显示分钟，缺少时间记录时只显示距离。手机端日期在左侧可用区域换行，避免覆盖右侧轮廓；旅行详情的本地预览提示置于导航下方，随页面滚出，避免遮挡封面信息。
2. **全程地图**：封面下方的灰色地图占满整个视口（`100dvh`，导航叠在地图上），在 `400svh` 的滚动区域内固定展示。下滑时黑色轨迹由起点延伸到终点，上滑时回退；终点留有完整路线的展示区间，再继续进入正文。完成后全程地图留在原位，正文白色页面从下方向上覆盖地图，与地图覆盖封面的衔接一致；向上滚动时反向揭开地图。地图按实际记录分段，不跨断点补线；支持按钮缩放和恢复全程视野，滚轮用于页面滚动。
3. **图文正文**：601px 及以上进入正文后才显示随行小地图和点位导航；600px 及以下隐藏这两项，直接阅读图文。点位和路段按内容自然排版，段间距为 32–64px，不设逐段屏高下限。标题右侧小字显示时间和海拔；最后几段即使都是短文字，也能在页面底部完成路线绘制。

电脑端（1024px 及以上）正文相对整页水平居中，宽度不超过 960px 或视口的 60%，并受屏高限制。正文图片（包括 Markdown 图片）居中并保留原比例，限制最大宽度和高度，4:3 横图与 3:4 竖图都可以完整放入一屏；封面仍使用全屏裁切。手机端正文使用完整可用宽度，移除随行地图和列表的顶部预留空间；图片高度仅扣除导航与阅读边距。

电脑随行地图占用居中正文左侧的一整栏，宽度根据剩余空间自动调整，并与正文、屏幕边缘保持间隔；高度延伸到导航下方至页面底部。601–1023px 的中等宽度使用左侧上下布局：地图适当增高，点位列表放在地图下方，正文使用右侧空间；地图高度最多占侧栏可用高度的 60%，为列表留出独立滚动空间。地图层不透明度为 60%，四边羽化。中央黑点保持清晰并始终居中，地图视角随轨迹插值连续移动。正文上滚时路线回退，地点标题同步反色。缩放按钮保持当前点居中，署名单独放在羽化区域外。600px 及以下隐藏随行地图及其按钮和署名，封面轮廓与全程地图仍正常展示。

点位导航按行程顺序排列，包含全部正文点位和路段，无额外标题。普通项为小号黑字且行距紧凑，当前阅读项放大、加粗，上下留白及行高同步展开，均用 0.36 秒过渡。点击可平滑跳转到相应正文；导航与随行地图共用阅读进度，上滚时也同步切换。1024px 及以上的电脑端导航固定在右侧空栏，距屏幕右边缘使用网站统一边距；601–1023px 放在左侧地图下方；600px 及以下隐藏。各宽度的阅读线与正文跳转均按视口和导航高度计算。长列表可单独滚动，当前项移出列表视口时自动滚入可见区域，不改变正文滚动位置。封面和全程地图阶段隐藏点位导航。系统减少动态效果时取消过渡并直接跳转。

网站继续使用 Jost / Noto Sans SC、共享导航字号、黑白配色和反色交互。详情页不设置独立返回箭头，通过“旅行”导航返回总览。

## 全程地图精选点位

在后台现有正文点位或路段上勾选“设为全程地图精选点位”，保存后全程地图使用该项的名称、时间和海拔。数据保存在正文项的可选布尔字段 `featured` 中；旧内容默认未精选，不自动代选。删除该正文项或替换 CSV 时，关联的精选选择也一起移除；调整锚点后使用新位置和记录。

路线到达精选位置时出现标记，并留出一段滚动距离供阅读，密集点位也能依次展示。一次只展示当前精选名称与元数据，避免文字重叠；已经到达的标记保留，可点击或键盘聚焦查看。路线回退至该位置之前时，标记随之隐藏。精选名称使用普通黑字，不反色，时间和海拔沿用正文格式；路段在其起点标注，展示起止时间及海拔范围。

`full-route-progress.ts` 将滚动进度映射为实际轨迹距离，`JourneyFullMap` 通过逐段裁切绘制黑线。系统启用“减少动态效果”时直接显示完整路线，并缩为一屏，不要求额外滚动完成动画。

## 时间与海拔

`journey.pointMeta` 是可选数组，与 `journey.segments.flat()` 按索引一一对应：

```ts
{ time: number | null; altitude: number | null }[]
```

时间以 Unix 秒存储，统一按北京时间 UTC+8 显示为 `25/9/29 5PM`：年份两位，月日不补零，小时使用 12 小时制及大写 AM/PM（午夜 12AM，正午 12PM）。海拔取整数，以无空格的大写 M 结尾，如 `1335M`，整组示例为 `25/9/29 5PM 1335M`。点位使用其锚点的记录，路段显示起止时间和海拔范围，如 `25/9/29 11PM–25/9/30 12AM 1100–1801M`。同一小时或同一海拔只显示一个值。缺失数据不推测、不补造；手绘新增点没有传感器记录，使用空值。海拔为 CSV 中的记录值，未使用地形服务校正。

`getStopMetadata` 负责格式与范围汇总；元数据在旅行载入后一次计算，不在每次滚动时重新扫描全程。CSV 导入、删除线路和手绘追加均保持元数据与坐标对齐。旧文档省略此字段时仍可读取，后续可从原始足迹补齐，正文与锚点无需重建。

## 数据与验证

当前内容保存在 Neon 的 `portfolio_travel`。生产与开发分支独立；同步前备份双方，在目标写入前核对版本及内容，完成后比对完整文档。源 CSV、备份和核验截图放在 Git 忽略的 `.local-preview/` 或项目外，不提交仓库。

新旅行通过[旅行后台](./travel-admin.md)导入及编辑，格式见 [CSV 导入](./travel-csv-import.md)。仓库中的 `src/data/example-journey.json` 是完全合成的演示数据，仅用于示例模式和显式初始化，不代表数据库中的实际旅行内容。配图与路线无地理对应关系，详见[示例说明](../examples/README.md)。
